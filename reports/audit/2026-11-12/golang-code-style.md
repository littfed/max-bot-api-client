## 1. Обзор требований стандарта `golang-code-style`

- **Ясность вместо хитрости («Clear is better than clever»):** Простота чтения кода;
- **Длина строк и переносы:** Разумная длина строк, семантический перенос длинных вызовов с 4+ параметрами;
- **Инициализация переменных:** `var` для нулевых значений, `:=` для значений с инициализатором;
- **Композитные литералы с именами полей:** Обязательное указание имен полей в структурах;
- **Минимизация вложенности (Guard Clauses):** Обработка ошибок в начале функции с немедленным выходом (`early return`), счастливый путь на левом крае отступа.

## 2. Результаты анализа кодовой базы

### 2.1. Минимальная вложенность и ранние возвраты
- Во всех методах пакетов [`pkg/maxbot`](file:///C:/mimocode/max-bot-api-client/pkg/maxbot) и [`pkg/bot`](file:///C:/mimocode/max-bot-api-client/pkg/bot) проверки предусловий и ошибок вынесены в начало функций:
  ```go
  if strings.TrimSpace(token) == "" {
      return nil, fmt.Errorf("bot token cannot be empty")
  }
  ```
  Это избавляет от «пирамид смерти» и глубоких ветвлений `else`.

### 2.2. Именованные композитные литералы
- Во всем коде инициализация структур (`maxbot.Client`, `maxbot.SendMessageRequest`, `gma.ChatCompletionRequest`, `http.Server`) выполняется строго с именованными полями. Позиционные литералы структур отсутствуют, что обеспечивает обратную совместимость при добавлении новых полей в API.

### 2.3. Инициализация мап и срезов
- Срезы и мапы инициализируются явно, без риска получения `nil map panic`:
  - `sessions: make(map[int64]*UserSession)`
  - `data: make(map[string]any)`
  - `routes: make([]route, 0)`
