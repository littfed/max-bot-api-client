---

## 1. Контекст проекта и протоколы интеграции

Проект `max-bot-api-client` взаимодействует с двумя внешними платформами:
1. **MAX Messenger Bot API** (`platform-api2.max.ru`): Официальный API мессенджера основан на протоколе **HTTPS REST / JSON** и получении входящих обновлений методом **Long Polling** (либо Webhooks). Платформа MAX не предоставляет публичный gRPC-шлюз.
2. **Go Model API (GMA)** (`gma.littfed.ru`): Протокол GMA следует стандарту **OpenAI REST / JSON** и Server-Sent Events (SSE) для стриминга ответов LLM.

---

## 2. Анализ применимости gRPC

### 2.1 Внешние интеграции (Внешний транспорт)
- **Статус:** ℹ️ **Неприменимо протоколами апстрима**
- Ни платформа MAX, ни GMA не поддерживают gRPC-эндпоинты. Попытка внедрения gRPC во внешний клиент невозможна без появления промежуточных прокси/шлюзов.

### 2.2 Политика Zero-Dependency библиотеки
- **Статус:** ✅ **Соответствует архитектурному ограничению**
- Добавление `google.golang.org/grpc` и `google.golang.org/protobuf` в `go.mod` привело бы к появлению тяжелых внешних зависимостей, что нарушило бы фундаментальный принцип нулевых зависимостей клиентского SDK (`max-bot-api-client`).

### 2.3 Перспективы: Внутренняя микросервисная шина (Future Work)
- **Статус:** 💡 **Архитектурная рекомендация для корпоративных инсталляций**
- Если бот-клиент будет вынесен в отдельный шлюзовой микросервис (Gateway), а бизнес-обработчики команд будут распределены по микросервисной инфраструктуре компании:
  1. **Protobuf контракты:** Рекомендуется описывать события бота в `.proto` файлах (`proto/bot/v1/events.proto`).
  2. **Bidirectional Streaming:** Использовать двунаправленные gRPC-стримы для доставки обновлений от `maxbot.Poller` к бэкенд-воркерам.
  3. **Статусы ошибок:** Возвращать клиенту и логгеру канонические gRPC коды (`codes.InvalidArgument`, `codes.Unavailable`, `codes.ResourceExhausted`).
  4. **Тестирование:** Применять `google.golang.org/grpc/test/bufconn` для in-memory интеграционных тестов без подъема реальных сокетов.

---

## 3. Итог

В текущей архитектуре REST/HTTP Long Polling полностью соответствует спецификациям MAX Messenger API и GMA, сохраняя чистоту и автономность Go stdlib. Включение gRPC не требуется и противоречит политике zero-dependency базового SDK.
