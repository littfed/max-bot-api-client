## 1. Контекст проекта и протоколы API

Проект `max-bot-api-client` — это Go SDK и исполняемый бот для платформы MAX Messenger Bot API.
- Протокол платформы MAX Messenger: **HTTP/REST с плоскими JSON-пейлоадами** (`/messages`, `/chats`, `/updates`).
- Протокол Go Model API: **OpenAI-совместимый HTTP REST + SSE streaming**.

---

## 2. Анализ применимости GraphQL

### 2.1 Клиентский транспорт
- **Статус:** ℹ️ **Неприменимо**
- Платформа MAX не предоставляет GraphQL эндпоинта. Все вызовы (отправка сообщений, управление кнопками клавиатур, загрузка файлов, получение обновлений) осуществляются через стандартные REST POST/GET/DELETE запросы.

### 2.2 Внутренняя архитектура и Zero-Dependency
- **Статус:** ✅ **Соответствует архитектурному ограничению**
- Библиотеки GraphQL в Go (`99designs/gqlgen`, `graphql-go`) требуют существенных внешних зависимостей, кодогенерации (`go generate`), парсеров схем SDL и рантайм-резолверов.
- Для бота на мессенджере добавление GraphQL создало бы избыточный оверхед (N+1 query complexity, CPU cost на парсинг GraphQL AST) без каких-либо функциональных преимуществ перед прямыми типизированными структурами Go (`maxbot.Message`, `maxbot.OutMessage`, `maxbot.Keyboard`).

### 2.3 Перспективы: GraphQL Gateway для админ-панелей
- **Статус:** 💡 **Архитектурная рекомендация**
- Если в будущем к боту потребуется разработать сложную web-панель управления (например, статистика диалогов, граф переходов FSM, визуальный конструктор сценариев и аналитика токенов GMA), GraphQL (`gqlgen`) может быть рассмотрен как отдельный админский BFF-микросервис (Backend-for-Frontend). В таком сценарии обязательными будут:
  1. Ограничение сложности (`extension.FixedComplexityLimit`) во избежание DoS.
  2. Использование per-request DataLoader'ов при загрузке истории пользователей.
  3. Отключение схемы Introspection в продакшн-окружении.

---

## 3. Итог

Архитектура проекта ориентирована на прямой REST/HTTP транспорт, что идеально соответствует спецификации MAX API и гарантирует максимальную производительность (порядка наносекунд на парсинг событий без AST-оверхеда) и нулевую зависимость ядра.
